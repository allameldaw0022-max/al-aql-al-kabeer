# العقل الكبير — موقع الشراكة والرعاية

موقع تعريفي بالقناة موجّه للرعاة، **ولوحة تحكم** يحدّث منها صاحب القناة كل شيء بنفسه:
النصوص، الأرقام، روابط السوشيال ميديا، رقم الواتساب، باقات الرعاية، وملف الرعاية (PDF) نفسه.

> القاعدة الأساسية في هذا المشروع: **لا قيمة ثابتة في الكود.** كل ما يظهر للزائر مصدره قاعدة البيانات.

## التقنيات

| الطبقة | الاختيار |
|---|---|
| الواجهة | Next.js 16 (App Router) + React 19 + TypeScript |
| التنسيق | Tailwind CSS v4 مع Design Tokens للهوية اللونية |
| قاعدة البيانات والمصادقة والتخزين | Supabase (Postgres + Auth + Storage) |
| الاستضافة | Vercel |

## الهوية اللونية

معرّفة كـ Design Tokens في `src/app/globals.css` تحت `@theme`، ومختبرة مقابل الخلفية البيضاء
لتحقيق تباين **WCAG AA**:

| الدور | الرمز | القيمة |
|---|---|---|
| الأساس | `canvas` | `#ffffff` |
| الذهبي (تعبئة وأزرار) | `gold-500` | `#c9a227` |
| الذهبي (نص على أبيض) | `gold-700` | `#8a6b12` |
| الأزرق الفاتح | `sky-400` | `#5fb6e4` |
| الأزرق (نص على أبيض) | `sky-600` | `#1e7fb4` |
| الحبر | `ink-900` | `#0f1d28` |

الأزرار الذهبية تستخدم نص `ink-900` لا الأبيض، لأن الأبيض على الذهبي لا يحقق تبايناً كافياً.

## التشغيل محلياً

```bash
npm install
cp .env.example .env.local   # ثم عبّئ القيم
npm run dev
```

## الإعداد الأولي لـ Supabase

1. أنشئ مشروع Supabase جديداً.
2. طبّق الهجرتين من `supabase/migrations/` بالترتيب (عبر SQL Editor أو `supabase db push`):
   - `20260906090000_site_content_schema.sql` — الجداول وسياسات RLS و bucket التخزين.
   - `20260906090100_seed_site_content.sql` — المحتوى الأولي بالأرقام الحقيقية من ملف الرعاية.
   - `20260906120000_harden_security_definer.sql` — تشديد أمني: نقل `is_admin()` إلى schema
     خاصة غير معروضة عبر PostgREST، وسحب صلاحية استدعاء دوال التريغر عبر RPC.
   - `20260906130000_block_role_changes_from_sessions.sql` — منع تغيير الدور من أي جلسة
     مستخدم، حتى لا يخفض الأدمن نفسه ويفقد الوصول.
3. انسخ `Project URL` و `anon key` من **Project Settings → Data API** إلى `.env.local`.

### إنشاء أول حساب أدمن

أنشئ المستخدم من **Authentication → Users → Add user**، ثم من SQL Editor:

```sql
update public.profiles
set role = 'admin'
where id = (select id from auth.users where email = 'البريد-هنا');
```

تريغر `protect_profile_role` يمنع تغيير الدور من **أي** جلسة مستخدم — بما في ذلك الأدمن
نفسه، حتى لا يخفض نفسه بالخطأ ويفقد الوصول. الترقية والخفض يتمان من SQL Editor فقط،
حيث `auth.uid()` فارغة.

## النشر على Vercel

اربط المستودع بـ Vercel وأضف المتغيرات الثلاثة من `.env.example`.

> **مهم:** متغيرات `NEXT_PUBLIC_*` تُحقن **وقت البناء**، لذا أي تعديل عليها يستلزم إعادة نشر.
> تعديلات المحتوى من لوحة التحكم لا تحتاج ذلك — تظهر فوراً.

## لوحة التحكم

على `/admin` (يتطلب حساباً بدور `admin`):

| الصفحة | ما تتحكم فيه |
|---|---|
| `/admin/settings` | اسم العلامة، نصوص الواجهة، البريد، رقم الواتساب ورسالته، روابط فيسبوك ويوتيوب وتيك توك |
| `/admin/stats` | كل الأرقام: المتابعون، المشاهدات، عدد الحلقات، متوسط التفاعل — مع إضافة وحذف وإخفاء وترتيب |
| `/admin/content` | نصوص أقسام: من نحن، الجمهور، لماذا تختارنا، طريقة التسعير |
| `/admin/packages` | الباقات ومزاياها، أيها مميزة، الترتيب، الإظهار والإخفاء |
| `/admin/deck` | رفع نسخة PDF جديدة تحل محل ملف الرعاية الحالي فوراً |

## بنية قاعدة البيانات

| الجدول | الدور |
|---|---|
| `site_settings` | صف واحد فقط (`id = 1`) — الهوية والتواصل والروابط ومسار ملف الرعاية |
| `site_stats` | كل الأرقام، مقسّمة إلى `platform` / `engagement` / `highlight` / `audience` |
| `content_blocks` | النصوص المتكررة، مقسّمة إلى `about` / `why` / `pricing` / `audience` |
| `sponsorship_packages` | باقات الرعاية ومزاياها |
| `profiles` | دور المستخدم (`viewer` / `admin`) |

القيم في `site_stats.value` نصية عمداً — لأن العرض يختلف بين `51K` و `793,000` و `+25` و `٢٥-٣٤`،
وصاحب القناة يكتبها كما يريد ظهورها.

## الأمان

- **RLS مفعّلة على كل جدول.** الزائر يقرأ الصفوف المرئية فقط؛ الكتابة محصورة بدور `admin`.
- **دالة فحص الصلاحية في schema `private`** غير معروضة عبر PostgREST، فلا نقطة RPC عامة.
- **التحقق من الدور على الخادم** في `requireAdmin()` مقابل قاعدة البيانات، لا من كوكي أو JWT claim.
- **منع تغيير الدور من الموقع** عبر تريغر على `profiles` — لا رفع صلاحية ولا خفضها.
- **روابط `https://` فقط** — التحقق يرفض `javascript:` وأي مخطط آخر.
- **رفع الملفات:** PDF فقط، بحد ٢٥ ميجابايت، محصور بالأدمن على مستوى Storage policy لا الواجهة فقط.
- **لا مفاتيح في الكود** — كلها Environment Variables.

## اختبارات جرت فعلياً

- `npm run build` و `npx eslint .` — نظيفان (البناء بمفاتيح المشروع الحقيقي).
- تصيير الصفحة العامة بكامل بياناتها مقابل خادم PostgREST وهمي: **٢٣ حقلاً ديناميكياً ظهرت جميعها**.
- حجب `/admin` عن غير المصادقين (تحويل `307` إلى `/login`).
- سلوك الاحتياط عند تعذّر الوصول لقاعدة البيانات: الصفحة تُصيَّر ولا تسقط.
- **١٠ اختبارات RLS على قاعدة البيانات الحقيقية** بانتحال أدوار `anon` و `authenticated`
  (قراءة المرئي فقط، منع الكتابة، منع الترقية الذاتية، صلاحيات الأدمن، سياسات التخزين) — كلها نجحت.
- **١٠ اختبارات إضافية بهوية حساب الأدمن الحقيقي** بعد إنشائه — كلها نجحت.
- **Supabase Security Advisor: صفر تحذيرات.**

### ما لم يُختبر بعد

اختبارات المتصفح الحقيقية (تسجيل الدخول، الحفظ من اللوحة، رفع واستبدال ملف الرعاية،
قراءة الصفحة العامة للبيانات المحدَّثة) لم تُنفَّذ — تحتاج تشغيل الموقع محلياً أو على Vercel.
